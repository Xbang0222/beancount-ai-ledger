# 提交信息规范

启用了提交钩子的仓库由 `scripts/hooks/commit-msg` 强制检查提交信息，不合规的提交会被拒绝。检查规则实现在 `scripts/ledgerlib/commitmsg.py`；已有提交可用 `python3 scripts/ledger.py commit-msg --range A..B` 逐条检查。

## 1 格式

```
类型: 摘要

正文（可选）
```

- 首行为 `类型: 摘要`：类型使用英文，摘要使用书面中文。
- 首行不得使用括号，不超过 80 字；细节空一行后写入正文。
- 一项业务一个提交。一笔业务（含往来两边的镜像分录）登记并校验通过后立即提交；配置了远程仓库的随即推送。不积压，不将无关的多笔业务合并为一个提交。

## 2 类型

| 类型 | 用途 |
|---|---|
| `feat` | 登记新业务、补记；脚本新功能 |
| `fix` | 更正、作废、对账调整；修复脚本缺陷 |
| `style` | 仅重排序时簿，余额不变 |
| `docs` | 文档 |
| `refactor` | 脚本重构 |
| `test` | 测试 |
| `chore` | 依赖、配置、同步上游脚本 |

## 3 涉及账本的提交

改动了账本文件的提交须同时满足：

- 类型只能是 `feat`、`fix` 或 `style`。
- 摘要以下列动词之一开头：登记、补记、更正、作废、对账、重排；科目表与建账使用新开、新建、初始化。
- 摘要依次写明账本、日期、业务、金额、结算方式。
- 摘要写明本次改动涉及的每一本账。账本称呼取自 `ledger.toml` 的 `title`：「个人账本」写作「个人账」。涉及哪些账本由钩子按改动的文件判定。

示例：

```
feat: 登记个人账10月28日午餐支出18.00元，微信付款
feat: 登记个人账与商店账10月28日代垫进货款200.00元，微信付款
feat: 补记个人账10月26日至27日交通支出两笔
fix: 更正个人账10月25日打车费，改记花呗付款
fix: 作废个人账10月27日重复登记的午餐支出18.00元
fix: 对账调整个人账银行卡差额0.60元，计入利息收入
style: 重排个人账9月序时簿，余额不变
feat: 新开个人账宠物支出科目
feat: 初始化个人账账户与期初余额
```

## 4 脚本与文档的提交

摘要使用动宾短语：

```
feat: 新增提交信息检查钩子
fix: 修正汇率缓存过期判断
docs: 新增宠物支出分类
chore: 同步上游脚本
```

## 5 书写约定

| 项目 | 写法 |
|---|---|
| 金额 | 保留两位小数并带「元」；外币写币种，如 `30.04 USD` |
| 日期 | 「10月28日」；跨日写「10月26日至28日」 |
| 结算方式 | 「支付宝付款」「微信收款」「信用卡付款」 |
