# 建账与账本存放

- 适用对象：AI。
- 读取时机：日常入账无需读取本文件；出现下表情形时读取对应一节。
- 相关文档：入账流程与强制约束见 `AGENTS.md`；提交信息规范见 `docs/COMMITS.md`；更正、对账、导入账单等请求见 `docs/AI-TASKS.md`。

| 情形 | 章节 |
|---|---|
| 首次接手本仓库，或 `doctor` 报告问题 | 1 第一次接手 |
| 需要确定账本的存放位置与同步方式 | 2 账本存放 |
| 用户没有远程仓库、不使用 Git，例如豆包等云电脑 | 3 没有远程仓库时 |
| `doctor` 提示账本未初始化，或用户要求建账 | 4 首次使用 |
| 用户不熟悉记账与技术操作 | 5 引导新手 |

## 1 第一次接手

执行 `python3 scripts/ledger.py doctor`。输出包括：依赖是否齐全、账本清单、账本是否已初始化、Git 远程仓库是否安全，以及下一步操作。按其提示逐项处理：

| `doctor` 的提示 | 处理 |
|---|---|
| 缺少依赖，或任一命令退出码为 3 | 执行 `python3 scripts/bootstrap.py`。官方源安装失败时脚本自动改用清华镜像重试；仍失败时以 `-i <镜像地址>` 指定其他镜像。依赖安装在仓库的 `.venv` 中，此后照常执行 `python3 scripts/ledger.py`，入口自动使用 `.venv`。不得使用 `--break-system-packages` 向系统 Python 安装依赖 |
| origin 指向公开的模板仓库，或远程仓库为公开 | 立即停止并告知用户，待用户拥有私有仓库后再提交账目。处理方式见 1.1 |
| 提交前自动检查未启用 | 执行 `git config core.hooksPath scripts/hooks`。此后每次提交自动执行账本校验、排版检查与提交信息检查，未通过则无法提交。`add` / `pair` / `amend` / `void` 成功后也会给出同样的提示 |
| 账套目录不是 Git 仓库 | 执行 `git init` 并提交。用户在自己的电脑上使用 Claude Code、Codex 等工具的，建议另建私有远程仓库，存放方式按第 2 节选择；只有云盘、没有远程仓库的按第 3 节处理 |
| 账本尚未初始化 | 按第 4 节引导用户 |
| 有账户超过若干天未与实际余额核对 | 请用户报出这些账户当前的实际余额，按 `docs/AI-TASKS.md`「余额核对」逐个核对。天数由 `ledger.toml` 的 `[ledger] reconcile_days` 设定，默认 35，0 为不提醒 |

### 1.1 建立私有仓库

- 在 GitHub 打开模板仓库，选择 Use this template，可见性选 Private。不得使用 Fork：公开仓库的 Fork 同样是公开的。
- 已安装 `gh` 且用户同意时，可代为执行 `gh repo create <仓库名> --private --template Xbang0222/beancount-ai-ledger --clone`。
- 已在模板的克隆中产生改动时：执行 `git remote rename origin upstream`，再执行 `git remote add origin <私有仓库地址>` 并推送。

## 2 账本存放

账本即本仓库所在的文件夹。在何种环境中运行（用户的电脑、云电脑、其他 AI 平台），就存放在该环境中跨对话保留的位置；须实际检查，不得凭推测判断。存储与同步方式按用户具备的条件依次选择：

| 优先级 | 条件 | 方式 |
|---|---|---|
| 1 | 私有的 Git 远程仓库（GitHub、Gitee、GitLab 等） | 每次改动后提交并推送，账本以远程为准。连接方式采用当前环境支持的方式（登录授权、令牌、仅限单个仓库的密钥均可）；需要用户操作的仅限授权一步，命令由 AI 执行。仓库必须为私有，`doctor` 会检查 |
| 2 | 只有云盘、网盘 | 按第 3 节在本地提交，并将 `backup` 生成的压缩包存入云盘 |
| 3 | 均不具备 | 照常在本地提交，并告知用户账本仅存于此一处，建议其另行备份 |

## 3 没有远程仓库时

适用于用户不使用 GitHub、没有远程仓库的环境。Git 照常在本地使用，无需账号与联网。相关操作全部由 AI 完成；不得要求用户学习 Git，也不向用户提及 Git。

本节以「AI记账」为例：账本目录为个人目录下的 `~/AI记账/ledger`，云盘中的备份文件夹同名「AI记账」。用户指定了其他位置的，以用户指定的为准。

### 3.1 确定存放方式

检查当前环境中是否存在跨对话保留的目录：个人目录是否为独立挂载的磁盘、其中是否留有以往对话的文件。须实际检查，不得凭推测判断。

| 检查结果 | 存放方式 |
|---|---|
| 存在。豆包云电脑的个人目录 `~` 属于此类：重启只清理系统盘，个人目录保留，任何对话均可读写 | 账本常驻 `~/AI记账/ledger`，云盘仅作备份，按 3.2 执行。不得将账本存放在当次对话的工作目录或 `/tmp` |
| 不存在，每次对话均为全新环境 | 账本以压缩包形式存于云盘，按 3.3 执行 |

### 3.2 账本常驻

每次开始时：

1. 进入 `~/AI记账/ledger`，执行自检：

   ```bash
   python3 scripts/bootstrap.py && python3 scripts/ledger.py doctor
   ```

2. `doctor` 的「账本」一节列出每本账的最后一笔。以通俗的表述告知用户，例如「账本里最后一笔是 10 月 3 日买菜 35 元」。用户当次的消息中已包含待记的账目时，报告后直接入账，无需等待回复。
3. 目录不存在时不得自行新建账本。先在云盘「AI记账」文件夹中查找文件名日期最新的 `ledger-backup-*.zip`：

   | 查找结果 | 处理 |
   |---|---|
   | 找到 | 下载并 `unzip` 到 `~/AI记账/`，得到 `ledger/`。告知用户原位置未找到账本、已从云盘某月某日的备份恢复，报出最后一笔请其核对，并说明该日之后的账目需要补记 |
   | 未找到 | 向用户确认是否为首次使用；确认后按 3.5 建账 |

每批改动后（入账、更正、修改规则均在此列）：

```bash
git add -A && git commit -q -m "feat: 登记个人账10月28日午餐支出18.00元、打车支出32.00元" && python3 scripts/ledger.py backup --daily
```

- 提交信息按 `docs/COMMITS.md` 书写。一批包含多笔时逐笔 `add`，全部入账后提交一次。
- `backup --daily` 在当日已备份时不执行任何操作；当日尚未备份时生成 `backups/ledger-backup-*.zip`。生成后须上传到云盘「AI记账」文件夹，并在回报中说明当日备份已存入云盘；上传未成功时须明确说明。
- 用户要求立即存入云盘时，去掉 `--daily` 再执行一次并上传。

### 3.3 账本存于云盘

1. 开始时从云盘「AI记账」文件夹取文件名日期最新的 `ledger-backup-*.zip`，`unzip` 得到 `ledger/`，在其中执行 3.2 的自检命令并报告最后一笔。用户指出最后一笔不符时，说明取得的是旧备份，须停止操作并查找最新的备份。云盘中未找到备份时不得自行新建账本，先向用户确认。
2. 每批改动后提交并打包（3.2 的命令去掉 `--daily`），将压缩包上传到云盘并在回报中说明已存入云盘；不得积压到对话结束。上传未成功时须明确说明，并将压缩包直接发送给用户，请其自行保存。

### 3.4 云盘备份的管理

- 一律使用 `backup` 生成的带日期时间的文件名上传，不得以同名文件覆盖：部分云盘会保留两个同名文件，无法区分新旧。
- 只保留最新的一份 `ledger-backup-*.zip`，改动历史已包含在压缩包内。新备份上传成功并确认在云盘中可见之后，方可删除更早的备份；只删除该文件夹中符合此命名的压缩包，不得改动其他文件。
- 找不到云盘工具时，先检查 `~/vm/resource-loader/bin/`：豆包云电脑的云盘工具 `lark-cli` 位于该目录，不在 PATH 中。仍找不到或无法连接云盘时，将压缩包作为文件直接发送在对话中，请用户自行保存，并明确说明本次未存入云盘。不得略过备份而不说明。
- 提示授权过期时，告知用户需要重新授权云盘、同意后即可、账本不受影响；授权完成后补存备份。

### 3.5 第一次建账

1. 将模板放入账本目录：`git clone --depth 1 https://github.com/Xbang0222/beancount-ai-ledger ~/AI记账/ledger`，随后删除其中的 `.git`，该目录是模板的历史，不属于用户。无法克隆时下载 `https://github.com/Xbang0222/beancount-ai-ledger/archive/refs/heads/main.zip` 并解压。
2. 按第 4 节与第 5 节建账。
3. 建账完成后建立本地仓库并提交，仅需执行一次：

   ```bash
   git init -q && git config user.name "记账助手" && git config user.email "ledger@localhost" && git config core.hooksPath scripts/hooks && git add -A && git commit -q -m "feat: 初始化个人账"
   ```

4. 执行 `python3 scripts/ledger.py backup`，将压缩包上传到云盘「AI记账」文件夹；文件夹不存在时新建。

`doctor` 提示账套目录不是 Git 仓库（旧版本遗留的账本）时，补做第 3 步。环境中没有 git 且无法安装时，跳过全部 git 命令，其余照常执行；此时无法查询改动历史。

### 3.6 其他

- 用户询问某笔账目的修改经过或原先的记法时，使用 `git log -p` 查询，并以通俗的表述告知结果。
- 未经实测的结论须说明是推断，不得表述为事实。命令报错时如实告知，不得绕过。
- `AGENTS.md` 的其余约束照常适用：只能通过命令入账，一次一笔，不得估算时间。推送一步略过。

## 4 首次使用

适用于 `doctor` 提示账本未初始化，或用户要求建账。

1. 一次问清：有哪些账户（银行卡、支付宝、微信、现金、信用卡、花呗等）、开账日期、各账户在开账日的期初余额、未说明支付方式时的默认结算账户。
2. 修改 `personal/accounts.beancount`：按用户的实际账户增删、更名，例如将 `Assets:Bank:Main` 改为 `Assets:Bank:CMB`；删除用不到的账户。
3. 在 `personal/opening.beancount` 登记期初：开账日前一日写 `pad`，开账日写 `balance`，负债写负数。
4. 修改 `rules/daily.md`：将第 3 节的结算账户对照表与默认结算账户改为用户的账户，并删除文件开头的模板提示，`doctor` 据此判断规则是否已修改。旧布局账本修改 `CATEGORIES.md` 第 0 节。
5. `check` 通过后提交，例如 `feat: 初始化个人账账户与期初余额`。

## 5 引导新手

适用于用户不熟悉记账与技术操作，或表示不清楚需要准备什么。此类用户通常初次接触记账，无法理解命令与科目；由 AI 引导，用户只需回答问题。

### 5.1 提问方式

一次只问一件事，使用通俗的表述并给出例子。不得一次列出清单让用户填写，不得使用「科目」「分录」「期初」「借贷」等术语。按下列顺序提问：

| 顺序 | 话术 |
|---|---|
| 1 | 「你平时的钱都放在哪？比如微信、支付宝、银行卡、现金，有几样说几样。」 |
| 2 | 「有没有欠着的钱？比如花呗、信用卡、白条、借别人的。」 |
| 3 | 逐个询问余额：「打开微信看一下零钱，现在是多少？」用户无法确定时请其报出大概数字，并说明日后可以对账更正 |
| 4 | 「平时付款最常用哪个？以后你没说怎么付的，我就默认记它。」 |

### 5.2 沟通要求

- 不向用户转述命令、文件名与报错原文；自行处理，只说明结果。出错时使用通俗的表述，例如「刚才没存上，我再试一次」。
- 建账完成后复述一遍，请用户确认：有哪些账户、各自的余额、欠款金额、默认结算账户。
- 随即引导用户记第一笔，例如：「现在试一下，告诉我你今天最近的一笔花销，比如『午饭 18，微信付的』。」入账后按 `AGENTS.md`「回报用户」的格式回报。
- 用户一次说出多笔、表述零散或夹杂闲聊均属正常情况：拆分后逐笔入账，无法确定的一笔单独询问，其余照常入账。

### 5.3 结束前的说明

向用户说明下列事项，每项一句话：

1. 日后如何开始：将 `docs/NO-GIT.md` 中「以后每次」的开场白原样发给用户，建议其保存到备忘录；有远程仓库的用户不需要。
2. 记错时如何处理：直接说「刚才那笔不对，应该是……」。
3. 可以询问的内容：「这个月花了多少」「我现在有多少钱」「这次旅行一共花了多少」。
4. 没有远程仓库的用户另行说明：云盘「AI记账」文件夹中是账本的备份，只有一个体积很小的压缩包，不要删除该文件夹。
