# 日常入账规则

> **这是模板，请改成你自己的。** 至少修改第 3 节的结算账户对照表与默认结算账户；`rules/classification.md` 的分类表按消费习惯增删。修改完成后删除本提示。

- 适用范围：全部账本的日常入账。
- 读取时机：每次入账前通读。
- 其余规则按 `AGENTS.md` 的文档索引按需读取。可用科目与摘要开头以 `python3 scripts/ledger.py brief` 的输出为准。

用户以口语描述收支，AI 转换为规范分录。写入账本的内容使用书面会计语言；回复用户时可使用口语。

## 1 分录要素

- 必填要素：日期、金额、会计科目、结算账户。标签按需标注，无适用标签时留空。
- 日期：用户未说明时取当日，按 `ledger.toml` 的 `timezone` 计算；「昨天」「上周五」等换算为具体日期；无法确定时向用户确认。
- 币种：默认本位币（`ledger.toml` 的 `base_currency`）。仅当用户明确提到外币时使用外币，且对应账户须允许该币种。
- 往来类科目（应收、应付）的摘要必须写明对方，例如「其他应收款-借给小王」「收回小王聚餐代垫款」。
- 摘要不写交易日期与时刻：日期由首行表达，时刻写入 `time:`，菜品、班次等细节写入 `note:`。正餐的事项写餐次，如「餐饮-午餐」。
- 转账、还款、借贷、投资等不涉及收支科目的业务，对方与摘要按 `rules/naming.md` 第 7 节的固定写法书写。
- 对方与摘要的写法见 `rules/naming.md`；科目归类见 `rules/classification.md`，或执行 `python3 scripts/ledger.py lookup <关键词>`。
- 归类由 AI 决定，不得询问用户。可以向用户确认的仅限事实：金额、日期、所属账本、业务性质（消费、借出或代垫）。业务性质不明时先确认，不得直接费用化。

## 2 账本与往来判定

只有一本个人账时跳过本节与第 4 节。

- 一本账对应一个会计主体。需要单独核算盈亏，或资金不完全归用户所有时才新建账本，例如店铺或工作室、家庭共同账、多人 AA 的活动经费、代管的资金：`python3 scripts/ledger.py new-book <名称> [--template business|minimal] [--link personal]`。
- 仅需统计某项事务的花费（一次旅行、装修、婚礼）时不新建账本，在个人账中使用标签（`rules/tags.md`）。
- 判定顺序：先确定业务归属（个人生活或店铺经营），再确定资金从哪个账户收付。二者共同决定记入哪本账、是否构成账本之间的往来。

| 业务归属 | 收付账户 | 处理 |
|---|---|---|
| 个人 | 个人账户 | 记入个人账 |
| 店铺 | 店铺账户 | 记入店铺账，不构成往来 |
| 店铺 | 个人账户 | 往来：按第 4 节两本账同时登记 |
| 个人 | 店铺账户 | 往来：按第 4 节两本账同时登记 |

各账本的记账范围登记在下表，AI 据此确定账本：

| 账本 | 记账范围 |
|---|---|
| `personal` | 个人与家庭的日常收支 |
| `shop`（示例） | 店铺经营：进货、物流、包装、推广、平台扣点、经营性订阅、销售收入 |

## 3 结算账户

先按第 2 节确定账本，再按用户所述的支付渠道确定结算账户：

| 用户表述 | 结算账户 |
|---|---|
| 微信、微信零钱 | `Assets:Wechat` |
| 支付宝、支付宝余额 | `Assets:Alipay` |
| 余额宝 | `Assets:Alipay:Yuebao` |
| 银行卡、银行（未指明哪张） | `Assets:Bank:Main` |
| 现金 | `Assets:Cash` |
| 信用卡 | `Liabilities:CreditCard` |
| 花呗 | `Liabilities:Huabei` |
| 白条 | `Liabilities:Baitiao` |
| 未说明支付方式 | 默认结算账户 `Assets:Alipay`，并在回报中写明 |

- 支付渠道不等于实际扣款账户：经支付宝支付可能扣余额、绑定的银行卡或花呗，经微信支付可能扣零钱或银行卡。默认按余额或零钱记；用户当次另有说明的，以当次说明为准。
- `accounts.beancount` 中的账户更名或新增结算账户后，本表与 `ledger.toml` 中 `[[naming.patterns]]` 的科目同步修改。
- 自有账户之间的划转不属于收支：借记转入账户，贷记转出账户，对方写转出方的机构，摘要「银行转账-<转出>转<转入>」。
- `STATE.md` 登记了临时默认结算账户的，在有效期内优先适用。

## 4 代垫与代收

账本之间的资金往来不确认收入或支出，两本账各记一边，每对镜像科目两侧余额合计恒为 0。两边使用 `ledger.py pair` 一次录入；`add` 遇到往来科目会拒绝。

往来科目由 `new-book --link` 生成。以个人账 `personal` 与店铺账 `shop` 为例：

| 情形 | personal 账 | shop 账 |
|---|---|---|
| 个人账户为店铺付款（代垫） | 借 `Assets:Receivable:Shop`，贷 付款账户 | 借 相应费用，贷 `Liabilities:OwnerLoan` |
| 店铺的款项进入个人账户（代收） | 借 收款账户，贷 `Liabilities:Shop` | 借 `Assets:Receivable:Owner`，贷 `Income:Revenue` |
| 店铺归还代垫款 | 借 收款账户，贷 `Assets:Receivable:Shop` | 借 `Liabilities:OwnerLoan`，贷 付款账户 |
| 个人将代收款转回店铺 | 借 `Liabilities:Shop`，贷 付款账户 | 借 收款账户，贷 `Assets:Receivable:Owner` |

- 店铺自有账户（记在店铺账内的银行卡、商户号）收付的款项直接记入店铺账，不构成往来。
- 个人账一侧的摘要不得写「主营业务成本」「主营业务收入」，该损益属于店铺。固定写法：对方写「商店」，摘要写「代垫商店采购款-<供应商>（股东往来）」「代收商店营业款-<渠道>（股东往来）」。
- 分红或提款属于投资回报，个人账确认收入，须先开立 `Income:Business` 等科目。不得以分红冲抵代垫债权，两类业务分别登记。
- 往来余额较大时可定期对冲，只保留净额，两本账各记一笔对冲分录。
- 更正或作废往来分录时两本账同步处理，并执行 `python3 scripts/ledger.py reconcile` 确认每对镜像科目合计为 0。
- 与他人共有的账本见 `rules/shared-books.md`。

`pair` 的输入为两段，每段首行是方括号内的账本名。任何一边不合规或两边金额不符时，两本账均不改动：

```bash
python3 scripts/ledger.py pair <<'EOF'
[personal]
2026-09-26 * "商店" "代垫商店采购款-某供应商（股东往来）"
  Assets:Receivable:Shop  200.00 CNY
  Assets:Wechat
[shop]
2026-09-26 * "某供应商" "主营业务成本-采购"
  Expenses:COGS  200.00 CNY
  Liabilities:OwnerLoan
EOF
```

## 5 与他人的往来、押金与预付

| 业务 | 处理 | 摘要 |
|---|---|---|
| 借给他人、为他人垫付 | 借 `Assets:Receivable:<对象>`；对象较少时使用 `Assets:Receivable:Other`。收回时冲减债权，不确认收入 | 「其他应收款-借给<对方>」「其他应收款-代垫<对方><事项>」；收回时「收回<对方><事项>」 |
| 向他人借款、他人代为垫付 | 贷 `Liabilities:Payable:<对象>`。归还时冲减负债，不确认支出 | 「借款-向<对方>借入」「其他应付款-<事项>」；归还时「偿还<对方>借款」 |
| AA 消费 | 仅本人份额计入费用，他人份额记应收；范例见 `examples/cookbook.beancount` | 按费用科目书写，如「餐饮-晚餐」；代垫对象与金额写入 `note:` |
| 可退押金 | 借 `Assets:Receivable:Other`。退回时冲减；被扣部分转入对应费用 | 「其他应收款-<事项>押金」；退回时「收回<事项>押金」 |
| 定金、预付的服务费（维修定金、课程预付） | 借 `Assets:Prepaid:Deposit`，服务完成后转入费用 | 「预付款项-<事项>定金」 |

对方一律写往来的另一方。完整对照见 `rules/naming.md` 第 7 节。

## 6 退款

- 退款冲减原支出科目，不确认收入；跨月退款同样冲减原科目。
- 摘要沿用原交易的开头，事项末尾加「退款」，写法见 `rules/naming.md` 第 6 节。

## 7 消费信贷

- 花呗、白条、信用卡消费时：借记费用，贷记对应的 `Liabilities:*`。
- 还款时：借记负债，贷记付款账户；还款不重复确认费用。对方写信贷机构或发卡行，摘要「偿还花呗」「偿还京东白条」「偿还<银行>信用卡」。
- 分期与贷款见 `rules/credit.md`。

## 8 时间

- 每笔交易均带 `time: "HH:MM"` 元数据，由 `add` / `pair` 自动注入录入时刻。补记历史交易时注入的同样是录入时刻。
- 用户明确给出时间时，在分录中写入 `time` 行，例如「昨天晚上 10 点」写 `time: "22:00"`，脚本不覆盖。
- 不得估算时间：用户未给出具体时间（包括仅说「晚上」「刚才」）时不写 `time` 行。无法判断上午或下午的时间表述（如「7 点半」）须先向用户确认。
- 当日交易的 `time` 晚于当前时间、交易日期晚于当日，均会被拒绝。
- 一律按 `ledger.toml` 的 `timezone` 记录，境外交易同样处理，不作换算。

## 9 标签

- 标签写在交易首行引号之后，不写入摘要；一笔交易可带多个标签。
- `STATE.md` 登记了进行中的行程及其默认标签的，交易发生日落在行程区间内时标注。
- 标签的类别、推断规则与登记表见 `rules/tags.md`。

## 10 分录范例

日常消费：

```
2026-09-26 * "面馆" "餐饮-午餐"
  Expenses:Food:Dining  18.00 CNY
  Assets:Wechat
```

信用消费与标签：

```
2026-10-02 * "火锅店" "餐饮-火锅" #trip #chengdu
  Expenses:Food:Dining  168.00 CNY
  Liabilities:Huabei
```

退款：

```
2026-10-24 * "拼多多" "餐饮-买菜退款"
  note: "关联：原单150.28，部分退货"
  Assets:Alipay          11.25 CNY
  Expenses:Food:Grocery
```

为他人垫付与收回：

```
2026-10-05 * "朋友小王" "其他应收款-代垫小王聚餐款"
  Assets:Receivable:Other  50.00 CNY
  Assets:Wechat

2026-10-08 * "朋友小王" "收回小王聚餐代垫款"
  Assets:Wechat            50.00 CNY
  Assets:Receivable:Other
```

自有账户之间转账：

```
2026-10-06 * "微信" "银行转账-微信转银行卡"
  Assets:Bank:Main  500.00 CNY
  Assets:Wechat
```

偿还花呗：

```
2026-10-09 * "蚂蚁花呗" "偿还花呗"
  Liabilities:Huabei  168.00 CNY
  Assets:Bank:Main
```

AA、信用卡还款、押金、贷款、基金、外币等范例见 `examples/cookbook.beancount`；各类非收支业务的对方与摘要见 `rules/naming.md` 第 7 节。
