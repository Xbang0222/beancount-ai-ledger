# 历史流水导入（专题）

- 适用范围：批量导入历史流水。来源不限：记账 App 的导出文件、支付宝与微信的账单、银行流水、信用卡账单、用户自制的表格，均适用同一套规则；各来源的差异只体现在字段名称与分类名称上，由第 2 节与 `rules/classification.md` 第 5.1 节的对照表消除。
- 读取时机：用户提供导出文件并要求导入；整理已导入的分录。
- 操作步骤见 `docs/AI-TASKS.md`「导入账单」；来源分类与科目的对照见 `rules/classification.md` 第 5.1 节。

## 1 原则

1. 导入的分录与日常入账适用同一套规则：科目按 `rules/classification.md` 归类，对方与摘要按 `rules/naming.md` 书写，写法检查同样生效。导入不构成例外。
2. 来源数据只作为事实依据。来源的分类、备注、商家名称不得原样写入科目、摘要与对方，须逐笔按规范改写。
3. 每一笔仍经 `add` 入账，不得直接写入序时簿。
4. 导出文件只在本地读取，不得提交。
5. 不得针对某一来源另立规则。来源特有的字段或分类先按第 2、3 节归入通用情形，再按通用规则处理。

## 2 字段对应

各来源的字段名称不同，按含义对应：

| 来源字段 | 处理 |
|---|---|
| 日期、交易时间、记账日 | 日期写入分录首行 |
| 时刻 | 写入 `time:`。该时间属于来源数据，不构成估算；来源只有日期时不写 `time:` |
| 分类、交易类型 | 按 `rules/classification.md` 第 5.1 节确定大类，再按备注中的具体物品或服务改判；来源没有分类时直接按商品说明与交易对方归类 |
| 备注、商品说明、交易摘要 | 原文写入 `note:`，以「<来源>备注：」开头注明出处，如 `note: "账单备注：9月21日成都到重庆"`。摘要按 `rules/naming.md` 第 4 节改写；原文中的日期、时刻、班次不得进入摘要 |
| 商家、交易对方、对方户名 | 按 `rules/naming.md` 第 3 节改写：营业执照名称、收单机构名称改写为店名简称或业务描述；缺失时写描述性统称；无法确定时写「未注明来源」「未注明对象」 |
| 账户、收付款方式 | 按 `rules/daily.md` 第 3 节的对照表确定结算账户 |
| 未指定账户 | 记默认结算账户，并在导入报告中列出笔数 |
| 金额与收支方向 | 支出、收入按方向记入收支科目；「不计收支」「其他」方向的记录按第 3 节判定 |
| 订单号、流水号 | 需要保留时写入 `note:`，不写入摘要 |
| 成员、项目、标签 | 转为标签，规则见 `rules/tags.md` |

备注为空且分类无法说明事项时：支出记 `Expenses:Other`，摘要「其他-未注明支出」；进账记 `Income:Other`，摘要「其他收入-未注明来源进账」；均在 `note:` 说明来源记录的情况，不向用户逐笔确认。

## 3 非收支记录

来源中的下列记录不属于收入或支出：

| 来源记录 | 处理 | 对方与摘要 |
|---|---|---|
| 转账、账户互转、提现、充值、银行卡转入零钱 | 自有账户之间划转 | `rules/naming.md` 第 7 节 |
| 信用卡、花呗、白条还款 | 冲减负债，不确认费用 | 同上 |
| 借入、借出、收款、还款 | 记应收应付，不确认收支 | 同上 |
| 报销款、他人归还的垫付款 | 冲减应收；原支出已费用化的冲减原科目 | 冲减原科目时摘要末尾加「退款」 |
| 退款 | 冲减原支出科目 | 摘要末尾加「退款」 |
| 基金、理财的申购与赎回 | 资金与金融资产之间的转换 | `rules/naming.md` 第 7 节 |
| 基金、理财的逐日收益 | `Income:Invest:PnL` | 「投资收益-基金当日收益」「投资收益-基金当日亏损」 |
| 平账、余额调整、余额变更 | 按第 4 节判定 | |
| 开账时补登的账户初始余额 | 并入期初余额，见第 5 节 | |

## 4 平账记录

平账记录是用户将来源中的账面余额改为实际余额时生成的差额，各来源称「平账」「余额调整」「余额变更」「余额校正」，不是一笔交易。不得原样记入 `Equity:Adjustment`，按下列顺序逐条判定。银行流水、支付平台账单没有平账记录，其与账面的差额直接按第 5 节处理。

| 顺序 | 判定条件 | 处理 |
|---|---|---|
| 1 | 同一时段内两个以上账户的平账此增彼减，金额相等或相近 | 推定为账户之间的划转，改记转账；转入基金、理财账户的改记申购，转出的改记赎回。金额不等的余数继续按第 2、3 条判定 |
| 2 | 基金、理财、黄金等市值随行情变动的账户，平账金额无法以划转解释的部分 | 估值变动，记 `Income:Invest:PnL`，摘要「投资收益-基金估值调整」 |
| 3 | 查得出对应业务的差额，例如同日的备注、其他账户的收付可以说明用途 | 按该业务补记 |
| 4 | 其余无法查明原因的差额 | 不登记分录，并入期初余额，见第 5 节 |

- 「同一时段」指同一日内相邻的平账记录；用户通常在一次对账中连续调整多个账户。
- 推定入账的分录在 `note:` 写明推定依据，如 `note: "来源以平账登记，按同期各账户余额变动推定为微信转入基金"`。

## 5 期初余额

- 开账日取导入范围内第一笔流水的日期。
- 期初余额以各账户当前的实际余额倒推：期初余额 = 核对日实际余额 − 开账日至核对日该账户全部分录的净发生额。实际余额由用户提供，取自各银行、支付平台当前显示的余额或来源的资产页。
- 在 `<账本>/opening.beancount` 以开账日前一日的 `pad` 与开账日的 `balance` 登记期初余额；全部流水导入后，以核对日次日的 `balance` 断言登记各账户的实际余额。两处断言均通过即表明期初余额与流水相符。
- 第 4 节第 4 条的差额与来源中补登的初始余额不单独登记，由倒推得出的期初余额吸收。
- 同一账户有多个来源时（例如记账 App 的记录与银行流水并存），以记录完整的一个来源为准，其余来源只用于核对与补漏，不重复入账。
- 倒推得出的期初余额明显不合理时，例如储蓄账户为负数，说明流水有遗漏或账户对应有误，先复核账户对照与转账推定，再向用户确认该账户的事实。

## 6 与日常余额核对的区别

| 情形 | 无法查明的差额 | 依据 |
|---|---|---|
| 历史流水导入 | 并入期初余额，不确认损益 | 导入前的账面从未与实际余额核对，差额是开账前余额与历次漏记的累积，无法归属到具体期间 |
| 日常余额核对 | 按 `rules/reconciliation.md` 确认为其他收入或财务费用 | 上一次核对之后的账面已与实际相符，差额发生在本期 |

导入完成并登记余额断言之后发生的差额，一律按日常余额核对处理。

## 7 导入报告

导入完成后执行 `check`，并向用户报告：

- 导入笔数、跳过的重复笔数；
- 改记为转账、申购、赎回与估值变动的平账笔数，并入期初余额的差额合计；
- 记默认结算账户的未指定账户笔数；
- 暂记 `Expenses:Other`、`Income:Other` 的笔数；
- 各账户的期初余额与核对日余额。
