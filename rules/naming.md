# 对方与摘要规范

- 适用范围：交易首行的对方（payee）与摘要（narration），以及 `note:` 元数据。日常入账与历史流水导入均适用。
- 读取时机：不确定对方或摘要的写法；入账被写法检查拒绝；登记转账、还款、借贷、投资等不涉及收支科目的业务。

机器可校验的写法规则只在 `ledger.toml` 的 `[naming]` 定义：摘要开头对照、括号内的固定标记、退款结尾、禁用的对方名称与笼统事项词、`note:` 的栏目、对方、摘要与 `note:` 中禁止出现的写法、固定场景、必须写 `note:` 的科目。对照表由 `python3 scripts/ledger.py brief` 或 `ledger.py rules` 输出。`add` / `pair` / `amend` 对不合规的分录直接拒绝并给出正确写法，`check` 扫描全部账本。本文件规定脚本无法判断的部分，并给出各类业务的标准写法。

## 1 原则

简洁、有信息量、保护隐私。摘要不重复科目、账户、日期已表达的信息；交易对象、行程等关系信息由标签表达；细节写入 `note:`。同一类业务的对方与摘要在全账保持一致，便于按摘要统计。

## 2 分录各层的职责

| 层 | 职责 | 示例 |
|---|---|---|
| 首行日期 | 交易发生日 | `2026-09-26` |
| `time:` | 交易时刻 | `time: "12:30"` |
| 科目 | 类别 | `Expenses:Food:Dining` |
| 对方 | 交易的另一方，写法见第 3 节 | 「面馆」 |
| 摘要 | 具体事项，固定格式的短句 | 「餐饮-午餐」 |
| `note:` | 分录其余部分未表达的事实：交易的标的、需要交代的情况、导入来源的备注原文 | `note: "明细：牛肉面、煎蛋"` |
| 标签 | 交易对象、行程、专项事务 | `#trip #chengdu` |

## 3 对方

| 情形 | 写法 |
|---|---|
| 餐饮、购物，用户说明了店名 | 店名简称，如「肯德基」「蜜雪冰城」「优衣库」 |
| 餐饮、购物，店名不明 | 描述性统称，如「餐馆」「食堂」「外卖」「便利店」「奶茶店」「菜市场」「网约车」「共享单车」 |
| 网购 | 平台名称，如「淘宝」「京东」「拼多多」；不写「卖家」「店家」「商贩」「摊主」等泛称 |
| 外卖订单 | 店名简称；店名不明时写「外卖」或「<品类>店」。不写外卖平台名，不写「<品类>外卖」 |
| 收款方显示为营业执照名称、个体工商户名称或收单机构名称 | 改写为店名简称或业务描述：「某市某区张记饭店」写「张记饭店」，「某某网络科技有限公司」写其品牌或「视频平台」 |
| 银行、信贷机构、基金销售机构 | 机构简称，如「招商银行」「蚂蚁花呗」「京东」「基金公司」 |
| 自有账户之间的划转 | 转出方的机构，如「微信」「招商银行」 |
| 工资、奖金、报销 | 「任职单位」或单位简称 |
| 个人往来 | 对方的称呼或姓名，如「朋友小王」「母亲」 |
| 经营账的客户 | 一律写「客户」，不写真实姓名 |
| 余额调整 | 账户所属机构，如「支付宝」 |
| 期初更正 | 「期初调整」 |
| 来源或对象无法确定 | 「未注明来源」「未注明对象」 |

不得使用「个人」「测试」「银行」「供应商」「商家」等空泛词：个人写称呼或姓名，银行写机构名称，供应商写固定名称，无法确定名称时写业务描述，如「服务器供应商」。

店名不明时，同一类对方使用同一个统称：

| 类别 | 统称 | 不使用 |
|---|---|---|
| 正餐堂食 | 「餐馆」 | 「餐厅」「饭店」「饭馆」 |
| 零售小店 | 「便利店」 | 「小卖部」「小超市」 |
| 专营单一品类的店铺、摊点 | 「<品类>店」「<品类>摊」，如「奶茶店」「烧烤摊」「小吃摊」 | 「奶茶外卖」「小吃街」「美食街」「夜市」 |
| 二手交易的买方 | 「二手买家」 | 「闲置物品买家」 |
| 无法指名的供应商、服务商 | 「<业务>供应商」「<业务>服务商」，如「服务器供应商」「报税服务商」 | 「服务器商」「税务服务」 |

上表「不使用」一栏的名称单独用作对方时由 `[[naming.forbidden]]` 拦截；店名中含有这些词的不受影响，如「张记饭店」。餐饮分录的对方写「美团」「饿了么」同样拦截。

## 4 摘要

### 4.1 格式

- 收支分录的摘要为「大类简称-事项」，如「餐饮-午餐」「交通-打车」「购物-外套」「居住-9月房租」。不写「XX支出」前缀，只使用一个「-」。
- 大类简称按所记科目固定，对照表见 `ledger.py rules`；一笔分录涉及多个收支科目时，按金额最大的科目确定。
- 不涉及收支科目的分录按第 7 节的固定写法书写。
- 记入 `Expenses:Other` 的分录摘要写「其他-<具体事项>」，如「其他-现金丢失」「其他-坏账损失」「其他-赔偿」，并必须写 `note:`，说明内容以及现有分类均不适用的原因。

### 4.2 事项的写法

事项写到能够区分业务的最小粒度，同类业务使用同一写法，不得使用「购物-日用品」「餐饮-消费」等笼统表述。

| 科目 | 事项写法 | 示例 |
|---|---|---|
| `Expenses:Food:Dining` | 餐次：早餐、午餐、晚餐、夜宵；饭卡充值写「饭卡充值」。餐次按用户表述确定，用户未说明时按 `time` 确定：05:00 至 10:29 为早餐，10:30 至 15:59 为午餐，16:00 至 20:59 为晚餐，其余为夜宵。菜品、餐种、店内细节写入 `note:`，如「明细：砂锅土豆粉」 | 「餐饮-午餐」「餐饮-夜宵」「餐饮-饭卡充值」 |
| `Expenses:Food:Snack` | 品类：奶茶、咖啡、饮料、饮用水、酒水、零食、小吃、甜品、香烟。一单多类按金额最大的品类书写。品名、品牌与口味写入 `note:`，如「明细：蛋挞」 | 「餐饮-奶茶」「餐饮-甜品」 |
| `Expenses:Food:Grocery` | 「买菜」，或单独购买的食材品类：水果、肉蛋奶、粮油、调料。品名写入 `note:`，如「明细：香蕉」 | 「餐饮-买菜」「餐饮-水果」 |
| `Expenses:Transport:*`、`Expenses:Travel:Transport` | 出行方式；城际交通写起讫地与票种。班次、座位写入 `note:` | 「交通-打车」「交通-地铁」「交通-成都至重庆高铁票」 |
| `Expenses:Shopping:*`、`Expenses:Housing:Daily` | 具体物品 | 「购物-蓝牙耳机」「居住-洗衣液」 |
| 按期发生的收支：房租、水电、话费、工资、会员 | 所属期间加事项，期间只写到月 | 「居住-9月房租」「工资收入-9月工资」 |
| `Expenses:Social` | 固定名目：「<事由>红包」「礼金」「生活费」「请客」「赠送<物品>」「捐款」。为他人的餐饮买单写「请客」，赠送实物与会员写「赠送<物品>」；交易对象由对方与标签表达，不写入摘要 | 「交际-生日红包」「交际-赠送衣服」「交际-请客」 |
| 其余科目 | 具体的物品或服务 | 「个护-理发」「医疗-感冒药」「文娱-视频会员」 |

### 4.3 不得写入摘要的内容

| 内容 | 去向 |
|---|---|
| 交易日期、时刻，如「12月21日」「19号」「20:10」 | 日期由分录首行表达，时刻写入 `time:`；班次、场次写入 `note:`。所属期间不在此列，可写「9月房租」 |
| 扣款账户、卡号尾号、金额构成明细 | 已由分录各行表达，不重复 |
| 交易对象、所属行程 | 标签 |
| 营业执照名称、订单号、流水号 | 对方按第 3 节改写；编号写入 `note:` |
| 括号内的补充说明 | `note:`。摘要中的括号只保留固定标记，清单见 `ledger.py rules` |
| 口语与冗长修饰 | 改写为书面短语 |

日期、时刻、注册全称、对方泛称，正餐、饮品零食、食材的事项不是餐次或品类，交际事项的口语写法，均由 `[[naming.forbidden]]` 拦截；其余由入账者遵守。

## 5 note 的写法

### 5.1 原则

`note:` 记录首行、标签、科目、金额与 `time:` 均未表达的事实，使用书面会计语言。没有此类事实时不写 `note:`。

| 原则 | 要求 |
|---|---|
| 自足 | 单读 `note:` 即可理解所述内容，不依赖摘要补全。为此允许重复摘要中的词，如摘要「个护-理发」，写「明细：理发2人」，不写「明细：2人」 |
| 句式固定 | 「明细」写「标的 + 数量」，所属期间写在最前；「说明」写「情况 + 处理」 |
| 用语统一 | 使用 5.3 的书面用语与数字写法，不使用口语 |
| 不写可查得的内容 | 交易对象、结算账户、余额核对的实际数与账面数，均由标签、分录或账面表达，不写入；账本之间的往来由另一本账的分录表达代付与收付的账户，不写入 |
| 不写信息缺失 | 时间、日期、对方不明时不作说明 |

### 5.2 栏目

`note:` 由「栏目：内容」组成，两栏之间以「；」分隔。栏目只有下表两项，「明细」在前，各至多一次；内容中不得再出现「：」「；」。栏目在 `ledger.toml` 的 `[naming.note_labels]` 定义，下表与其保持一致，由 `tests/test_docs_examples.py` 检查；增删栏目时二者同步修改。

| 顺序 | 栏目 | 内容 | 句式 | 示例 |
|---|---|---|---|---|
| 1 | 明细 | 交易的标的：品名、人数、晚数、所属期间、金额构成 | 〔期间〕标的〔数量〕 | `明细：牛肉面、煎蛋`、`明细：酒店住宿2晚` |
| 2 | 说明 | 需要交代的情况：分次支付、冲减的原交易、金额的确定方法、待确认事项 | 情况〔处理〕 | `说明：分3笔支付6.00、5.00、8.00`、`说明：冲减11月2日原交易73.80` |
| 末段 | <来源>备注 | 导入来源的备注原文，照录，不改写，不受格式检查 | — | `账单备注：9月21日成都到重庆` |

多数分录只有「明细」或不写 `note:`；「说明」只用于有特殊情况的分录。

### 5.3 用语与数字

| 项目 | 写法 | 不使用 |
|---|---|---|
| 动词 | 购入、支付、退回、冲减、计入、预发、扣抵、补记、分摊、结清、确定、待确认 | 买、给、点的、先行、抵掉、记成、倒推、待补 |
| 并列的品名或金额 | 以「、」分隔，如「牛肉面、煎蛋」「6.00、5.00、8.00」 | 连写、以「+」连接 |
| 数量 | 数字加量词，置于标的之后，如「理发2人」「住宿2晚」「第2笔采购」 | 「2人理发」「前两晚」 |
| 期间 | 写全，如「6月至7月」 | 「6-7月」 |
| 金额 | 阿拉伯数字，保留两位小数；本位币不带单位，与其他币种并列时写币种名称；其他币种写代码，如「20.05 USD」 | 「6+5+8」「2000元」 |
| 日期 | 「11月2日」 | 「11.2」「2号」 |
| 账户 | 简称，如「店铺经营卡」「对公账户」 | 尾号 |

内容写名词性短语，不加句号，末尾不加标点；全文不超过 60 字，导入来源的备注原文不计，上限由 `[naming] note_max` 定义。

### 5.4 各类业务的写法

| 业务 | 写法 | 示例 |
|---|---|---|
| 正餐、饮品零食、食材 | 用户说明了品名时写「明细」 | `明细：牛肉面`、`明细：牛奶` |
| 多人消费 | 标的加人数 | `明细：理发2人` |
| 住宿 | 地点、标的、晚数 | `明细：成都酒店住宿2晚` |
| 城际交通 | 班次、座位 | `明细：G8501次二等座` |
| 含多项内容的款项 | 各项以「、」分隔，可带金额 | `明细：本金500.00、利息30.00` |
| 换汇 | 写在未以 `@@` 表达成本的一方 | `明细：人民币2000.00购入300.00 USD，汇率6.6667` |
| 补记 | 补记的次数与累计次数 | `明细：补记定投1次，累计13次` |
| 一次消费分次支付，合记一笔 | 笔数与各笔金额 | `说明：分3笔支付6.00、5.00、8.00` |
| 同一餐记为多笔分录 | 各笔均写明 | `说明：同一餐分2笔支付` |
| 退款 | 原交易的日期与金额 | `说明：冲减11月2日原交易73.80` |
| 定金、押金的抵扣 | 抵扣的款项与金额 | `说明：扣抵3月3日预付定金100.00` |
| 金额按余额确定 | 确定方法 | `说明：金额按余额差额确定` |
| 实际情况与摘要不同 | 实际情况与经确认的处理 | `说明：余额短少10.00用途未明，经确认计入零食` |
| 待确认的事项 | 事项 | `说明：税种待确认` |
| 记入 `Expenses:Other` | 必须写「明细」 | `明细：赔偿邻居门锁` |

下列内容不写入 `note:`：账本之间的往来由哪个账户代付或代收；余额核对的实际数与账面数；定投等规则已固定的扣款安排。

### 5.5 校验

| 检查项 | 配置 | 内容 |
|---|---|---|
| 栏目 | `[naming.note_labels]` | 每段以表中的栏目开头，顺序与次数不符即拒绝 |
| 字数 | `[naming] note_max` | 超过上限即拒绝 |
| 必写 note 的科目 | `[naming] note_required` | 记入 `Expenses:Other` 必须写 `note:` |
| 禁用写法 | `[[naming.forbidden]]` 中 `field = "note"` 的规则 | 口语、自造文言缩略、句号与末尾标点、处理过程用语、账户尾号、金额写法、信息缺失的说明、对账数字、以加号连写的金额、只有数量的明细、连写的期间；带 `tag`、`account` 的规则只在分录带该标签、涉及该科目时生效 |
| 必写内容 | `[[naming.required]]` | 可按科目规定 `note:` 必须写明的内容，默认不配置 |

各项均不检查导入来源的备注原文。自足与句式由入账者按本节执行，脚本只拦截明显不合规的写法。现行规则见 `ledger.py rules`；`add` / `pair` / `amend` 拒绝不合规的分录，`check` 扫描全部账本。

### 5.6 导入的分录

批量导入的分录，不论来源是记账 App、支付平台账单还是银行流水，均将来源的备注原文写在 `note:` 末段，以「<来源>备注：」开头，照录，不改写；入账时的推定写在其前的「说明」栏。摘要按第 4 节改写，不得照抄备注。规则见 `rules/import.md`。

```
2026-09-21 * "客运" "交通-成都至重庆车费"
  note: "说明：付款账户按微信零钱确定；账单备注：9月21日成都到重庆"
  Expenses:Transport:LongDistance  98.00 CNY
  Assets:Wechat
```

## 6 退款与差额

- 退款、退回沿用原交易的摘要开头，事项末尾加「退款」，如「餐饮-买菜退款」；经营账的客户退款固定写「销售退回」。退款冲减原分类，不确认收入。
- 余额核对的差额不属于退款，处理与写法见 `rules/reconciliation.md`。

## 7 非收支业务的固定写法

下列业务不涉及收支科目，摘要没有大类简称，对方与摘要按本表书写。自有账户之间的划转、负债的借入与偿还由 `ledger.toml` 的 `[[naming.patterns]]` 校验。

| 业务 | 对方 | 摘要 | 示例 |
|---|---|---|---|
| 自有账户之间转账 | 转出方的机构 | 「银行转账-<转出>转<转入>」 | `"微信" "银行转账-微信转招行"` |
| 取现、存现 | 银行 | 「银行取现」「银行存现」，可加「-<用途>」 | `"招商银行" "银行取现-旅行备用金"` |
| 与他人以现金兑换电子余额 | 兑换对象 | 「现金兑换<转入账户>」 | `"朋友小王" "现金兑换微信零钱"` |
| 偿还花呗、白条、信用卡 | 信贷机构、发卡行 | 「偿还<产品>」 | `"蚂蚁花呗" "偿还花呗"`、`"京东" "偿还京东白条"`、`"招商银行" "偿还招行信用卡"` |
| 贷款放款、向他人借入 | 出借方 | 「借款-<事项>」 | `"国家开发银行" "借款-助学贷款放款"`、`"朋友小王" "借款-向小王借入"` |
| 归还借款本金 | 出借方 | 「偿还<出借方>借款」 | `"朋友小王" "偿还小王借款"` |
| 他人代为垫付、代收待转付 | 对方 | 「其他应付款-<事项>」 | `"同事小李" "其他应付款-小李代垫打车费"` |
| 借给他人、为他人垫付 | 对方 | 「其他应收款-借给<对方>」「其他应收款-代垫<对方><事项>」 | `"朋友小王" "其他应收款-代垫小王聚餐款"` |
| 收回借出款、垫付款、押金 | 对方 | 「收回<对方><事项>」 | `"朋友小王" "收回小王聚餐代垫款"`、`"房东" "收回租房押金"` |
| 支付可退押金 | 收取方 | 「其他应收款-<事项>押金」 | `"房东" "其他应收款-租房押金"` |
| 支付定金、预付服务费 | 收取方 | 「预付款项-<事项>定金」 | `"维修店" "预付款项-手机维修定金"` |
| 基金、股票的买入与定投 | 销售机构或「基金公司」 | 「申购基金」「指数基金定投」「买入股票」 | `"基金公司" "指数基金定投"` |
| 基金、股票的赎回与卖出，不含价差 | 同上 | 「赎回基金」「卖出股票」 | `"基金公司" "赎回基金"` |
| 买入、卖出黄金 | 销售机构 | 「买入积存金」「卖出积存金」 | `"招商银行" "买入积存金"` |
| 期初余额更正 | 「期初调整」 | 「期初调整-<事项>」 | `"期初调整" "期初调整-补登开账前借出款"` |
| 余额调整暂记 | 账户所属机构 | 「余额调整-账实差异」 | `"支付宝" "余额调整-账实差异"` |

- 分录含收支科目时按该科目的大类简称书写：含利息的贷款还款写「财务费用-<贷款>利息」，本金与利息的金额写入 `note:`；含价差的赎回与卖出写「投资收益-赎回<标的>」；现金分红写「投资收益-<标的>现金分红」；基金逐日收益写「投资收益-基金当日收益」「投资收益-基金当日亏损」。
- AA 消费中本人份额与代垫份额记在同一笔时，摘要按费用科目书写，如「餐饮-晚餐」，代垫对象与金额写入 `note:`。
- 往来类科目的摘要必须写明对方。

## 8 账本之间往来的固定写法

| 账本 | 业务 | 对方 | 摘要 |
|---|---|---|---|
| 个人账 | 代垫 | 「商店」 | 「代垫商店采购款-<供应商>（股东往来）」 |
| 个人账 | 代收 | 「商店」 | 「代收商店营业款-<渠道>（股东往来）」 |
| 个人账 | 收回代垫款 | 「商店」 | 「收回商店代垫款（股东往来）」 |
| 个人账 | 转回代收款 | 「商店」 | 「归还商店代收款（股东往来）」 |
| 店铺账 | 归还股东垫付款 | 「股东」 | 「归还股东垫付款（股东往来）」 |
| 店铺账 | 收回股东代收款 | 「股东」 | 「收回股东代收款（股东往来）」 |

- 个人账一侧不得写「主营业务成本」「主营业务收入」，该损益属于店铺。
- 店铺账一侧的代垫、代收按经营科目的大类简称书写，对方写供应商或「客户」，如 `"某供应商" "主营业务成本-采购"`。
- 「（股东往来）」是固定标记，须列入 `[naming].markers`。
