# 归类判例

- 适用范围：「用户表述 → 分录处理」的既有判例，用于归类和易错业务的比照。
- 读取方式：按需检索（`python3 scripts/ledger.py lookup <关键词>`），不必通读。
- 维护：出现本文件未覆盖的新情形时，按 `rules/classification.md` 第 2 节处理，并将判例追加到对应表格。

表内约定：摘要格式为「大类简称-事项」，事项的写法见 `rules/naming.md` 第 4.2 节；对方写店名或描述性统称；结算账户按 `rules/daily.md` 第 3 节确定，表内不重复；科目省略 `Expenses:` 前缀。

## 2 易错情形

| 用户表述 | 处理 | 依据 |
|---|---|---|
| 和朋友 AA，我先付了 200，他当场转我 100 | 记 200 餐饮，收到的 100 冲回餐饮 | AA、报销退回冲原分类，不算收入 |
| 请朋友吃饭 | `Social`，不记 `Food` | 请客性质是交际 |
| 帮朋友小王垫付了 50 | 挂 `Assets:Receivable:<对方>`，摘要「其他应收款-代垫小王<事项>」 | 借出、代垫不是消费，不得费用化 |
| 帮人代充会员，收了 30，进价 25 | 收的 30 记 `Income:SideBiz`「副业收入-代充会员」，进价 25 记 `Expenses:SideBiz`「副业成本-代充会员进价」 | 小生意收款和进价分开记，不只记差价 5 |
| 退了件衣服，钱退回来 | 原分类 `Shopping:Clothes` 记负数，摘要「购物-外套退款」 | 退款冲原分类，不是收入 |
| 交房租押金 | 押金记 `Assets:Receivable:Other`，摘要「其他应收款-租房押金」；只有房租进 `Rent` | 押金能退，是资产 |
| 修手机先付了定金 | 定金记 `Assets:Prepaid:Deposit`，摘要「预付款项-手机维修定金」；修好后转入 `Service:Life` | 服务尚未提供，先记预付，不直接费用化 |
| 微信提现到银行卡 | 两个资产账户之间划转，对方「微信」，摘要「银行转账-微信转招行」；手续费另记 `Finance:Fee` | 自有账户之间划转不是收支，写法见 `rules/naming.md` 第 7 节 |
| 还花呗 / 还信用卡 | 借负债、贷付款账户，摘要「偿还花呗」「偿还招行信用卡」 | 消费时已记费用，还款不重复确认 |
| 摘要想写「12月21日成都到重庆车票」 | 摘要「交通-成都至重庆车票」，班次写入 `note:` | 日期由首行表达，摘要不带日期与时刻 |
| 在成都吃饭 | 照常 `Food:Dining`，打 `#trip` `#chengdu` | 旅行期间吃饭不改科目，靠标签归集 |
| 和家人一起吃 | 照常 `Food:Dining`，打 `#family` | 跟谁花的靠标签，不新开分类 |
| 和伴侣逛街买了衣服，没说给谁买 | 照常 `Shopping:Clothes`，打 `#partner` | 未说明时按共同消费记原科目 |
| 给伴侣买了件衣服 | 摘要「交际-赠送衣服」，`Social`，打 `#partner` | 仅为对方购买才记交际；摘要不写「给伴侣」，对象由标签表达 |
| 用个人的卡给店里进货 | 经营账 `COGS`；个人账按往来记两边 | 先看业务归属，店里进货是店里的 |
| 帮店里买了个服务器 | 经营账 `Tools` | 经营用工具，不算个人订阅 |
